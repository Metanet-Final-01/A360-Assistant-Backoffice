# P1. 최종 검색 파이프라인

## 처리 순서

```text
질문
→ BM25(키워드) + Vector(의미) 각각 검색
→ RRF로 결합(Hybrid)
→ Candidate Pool
→ Reranker(Voyage rerank-2.5-lite)
→ Final Top-K
→ 답변 생성
```

## 확정값

| 항목 | 값 | 상태 |
|---|---|---|
| Chunk size | **1200자** (char 기준) | ✅ 확정 |
| Overlap | **10%** (120자) | ✅ 확정 |
| 검색 방식 | BM25 + Vector | ✅ 확정 (Vector-only 대비 압도적 개선, P3 참고) |
| 결합 방식 | RRF (rrf_k=60, 가중치 1:1) | ✅ 현재 운영값 — 정규화 융합(min-max+arithmetic_mean)이 더 나을 수 있다는 신호 있으나 실측 검증 진행 중(P4 참고) |
| Candidate pool | 50(branch당) | ✅ 현재 운영값 — 100~150 확장 시 이득 있는지 검증 중 |
| Reranker | Voyage rerank-2.5-lite | ✅ 확정 |
| Rerank 후보 수 | 20 | ✅ 현재 운영값 — 50까지 늘려도 결과 동일함을 확인(비용만 증가, P4 참고) |
| Final top-k | 5 | ✅ 확정 |

## 이 페이지에서 전달할 내용

> **문서 분할부터 최종 검색 결과까지 핵심 설정을 확정했다. Chunk size·Overlap·검색 방식(Hybrid+Rerank)은 충분히 검증되어 확정 상태이며, 융합 방식·candidate pool 세부 튜닝은 추가 개선 여지를 검증하는 중이다.**
