# 평가지표 설명

## RAGAS란?

**RAGAS**(Retrieval Augmented Generation Assessment) — RAG 파이프라인을 평가하기 위한 오픈소스 프레임워크. LLM을 "판정자(judge)"로 써서 검색된 문서와 생성된 답변의 품질을 자동으로 채점한다. 이 프로젝트에서는 judge로 gpt-4o-mini(초기) 또는 로컬 EXAONE-4.0(이후 전 단계)을 사용.

RAGAS가 제공하는 지표 중 이 프로젝트에서 쓴 5가지:

| 지표명 | 무엇을 재나 | 필요한 입력 |
|---|---|---|
| **Faithfulness** | 생성된 답변이 검색된 문서 내용에 충실한가(할루시네이션 없이) | 답변 + 검색된 문서 |
| **AnswerRelevancy** | 답변이 질문과 얼마나 관련 있는가 | 질문 + 답변 |
| **ContextPrecision** (LLMContextPrecisionWithReference) | 검색된 문서 중 실제로 정답 도출에 필요한 문서의 비율(정밀도) | 질문 + 검색된 문서 + 정답 |
| **ContextRecall** | 정답을 구성하는 데 필요한 정보가 검색된 문서에 얼마나 포함됐는가(재현율) | 질문 + 검색된 문서 + 정답 |
| **AnswerCorrectness** | 생성된 답변이 정답과 얼마나 일치하는가 | 답변 + 정답 |

**중요**: ContextPrecision·ContextRecall(WithReference 버전)은 **생성된 답변 없이도** 채점 가능 — 질문·검색된 문서·정답(reference)만 있으면 됨. 그래서 검색 단계만 별도로 빠르게 평가할 수 있었음.

## 자체 계산 지표 (RAGAS가 아니라 직접 계산한 것들)

RAGAS는 LLM이 판정하는 지표라 채점 비용·시간이 들고 주관이 섞일 수 있음. 그래서 "정답 문서 ID"를 gold(정답)로 미리 정해두고, LLM 없이 기계적으로 계산하는 지표를 병행함 — 이쪽은 판정 흔들림이 없어 신뢰도가 더 높음.

| 지표명 | 정식 명칭 | 무엇을 재나 |
|---|---|---|
| **Hit@1 / Hit@3 / Hit@5** (Gold Document Hit@K) | 검색 결과 상위 K개 안에 정답 문서가 있으면 1, 없으면 0 | 검색이 정답 문서를 "찾아내기는 했는가"(순위 무관, K 안에만 있으면 성공) |
| **MRR** (Mean Reciprocal Rank, 정확히는 케이스 평균이라 reciprocal_rank) | 정답 문서가 처음 등장한 순위의 역수(1등=1.0, 2등=0.5, 3등=0.33...) | 정답 문서가 "몇 등으로" 나왔는가 — Hit@K보다 순위에 더 민감 |
| **EvidenceCoverage** | 정답 근거 스니펫(정답을 구성하는 실제 문장)이 검색된 문서들 안에 얼마나 포함됐는가(문자열 매칭) | 검색 결과가 "정답을 만들 재료를 충분히 담았는가" — ContextRecall과 비슷하지만 LLM 판정이 아니라 기계적 문자열 매칭이라 더 객관적 |

## 우리가 특히 집중한 지표: Context Precision과 Context Recall

### 왜 이 둘인가

이 프로젝트의 핵심 질문은 "chunk_size/overlap/검색방식을 어떻게 정해야 하는가"였고, 이건 결국 **검색 단계의 품질** 문제다. RAGAS 5개 지표 중:

- Faithfulness·AnswerRelevancy·AnswerCorrectness는 **생성 단계**(LLM이 얼마나 잘 답했는가)를 재는 지표라, 검색이 아무리 좋아도 생성 모델 자체의 능력에 좌우됨
- **ContextPrecision·ContextRecall만 검색 결과 자체의 품질**을 직접 잰다 — "필요 없는 문서까지 가져왔는가(정밀도)"와 "필요한 문서를 놓쳤는가(재현율)"

즉 chunk_size/overlap/검색방식처럼 **검색 파이프라인을 튜닝하는 문제에서는 Precision·Recall이 가장 직접적인 목적함수**이고, 생성 품질 지표들은 그 결과로 따라오는 하위 지표로 취급했다.

추가로 실용적인 이유: **ContextPrecision·ContextRecall(WithReference)은 답변 생성 없이도 채점 가능**해서, 검색 하이퍼파라미터를 스크리닝할 때 생성 비용(로컬 LLM이라도 시간이 듦) 없이 빠르게 비교할 수 있었다.

### 둘의 조화평균(HM)

Precision과 Recall은 트레이드오프 관계라(청크를 넉넉히 가져오면 Recall은 오르지만 Precision은 내려갈 수 있음) 하나의 숫자로 비교하려면 평균이 필요한데, **산술평균이 아니라 조화평균(Harmonic Mean)**을 쓴다 — 둘 중 하나가 극단적으로 낮으면(예: Recall 1.0인데 Precision 0.1) 산술평균은 이를 가려버리지만(0.55), 조화평균은 낮은 쪽에 훨씬 민감하게 반응해서(0.18) "둘 다 골고루 좋아야 높은 점수"를 강제한다.

```text
HM = 2 × Precision × Recall / (Precision + Recall)
```

(F1-score와 정확히 같은 공식 — Precision/Recall의 조화평균이 F1-score라는 이름으로 더 잘 알려져 있음)
