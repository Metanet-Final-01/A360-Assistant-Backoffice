# chunk_size / overlap 확정 — 핵심 결론 (PPT 슬라이드용)

## 확정값

| 항목 | 확정값 |
|---|---|
| chunk 방식 | char 기준 |
| chunk_size | **1200자** (≈ token 900~1024토큰과 실제 크기 동일) |
| overlap | **10%** (120자) |

---

## 숫자로 보는 근거

| 비교 | 결과 |
|---|---|
| 300자 → 1200자 | EvidenceCoverage **0.497 → 0.701** (+20.4%p) — 작은 청크는 근거가 잘려나감 |
| 1200자 → 1500자 | EvidenceCoverage **0.701 → 0.716** (+1.5%p) — 더 키워도 거의 안 늘어남(포화) |
| overlap 0% → 10% (chunk=1200) | ContextPrecision **0.811 → 0.839**(+2.8%p), ContextRecall **0.872 → 0.884**(+1.2%p) |
| overlap 10% → 20% (chunk=1200) | ContextPrecision 0.839 → 0.816 (오히려 하락) |

→ **1200자/10% overlap이 "이득이 꺾이기 직전의 마지막 지점".** 그 밑은 손해, 그 위는 공짜 이득 없음.

---

## 검증 규모 — 이 결론은 감이 아니라 반복 확인된 것

- char/token 14개 후보 × RAGAS 5종 + 검색 3종 지표, 129건 골드셋 전체로 스크리닝
- 실제 크기 매칭쌍(cs1200↔tok900, cs1500↔tok1024)으로 **paired 유의성검정 3라운드(Wilcoxon/bootstrap/McNemar), 총 115개 검정 — 방향이 뒤집힌 적 0건**
- overlap은 gpt-4o-mini로 4개 크기 × 3개 비율(0/10/20%) 전수 테스트, 로컬 EXAONE hybrid+rerank로 재확인까지 완료

---

## 통계적 주의사항 (한 줄)

> 115개 이상의 검정에서 "1200/10%가 다른 값보다 확실히 더 낫다"는 신호는 못 찾았다 — 그러나 방향이 한 번도 뒤집히지 않았다는 게 핵심. 즉 **"확실한 승자"가 아니라 "115번 찔러봐도 손해가 안 나는, 가장 방어 가능한 선택"**.
