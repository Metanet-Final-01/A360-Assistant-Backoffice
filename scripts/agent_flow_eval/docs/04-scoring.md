# 4. 채점 — 우리가 만든 지표

전처리가 끝나면 정답과 예측 각각에서 **채점 대상 액션 목록**이 나온다. 이제
둘을 비교한다.

## 기본 아이디어 (한 줄)

> **정답 액션과 예측 액션을 1:1로 짝짓고, 짝지어진 개수로 Precision / Recall /
> F1을 계산한다.**

익숙한 분류 문제 채점과 똑같다.

```
TP (맞춤)      = 짝지어진 개수
FP (헛발질)    = 예측에만 있고 짝 못 찾은 것
FN (빠뜨림)    = 정답에만 있고 짝 못 찾은 것

Precision = TP / (TP + FP)    "만든 것 중 맞는 게 얼마나 되나"
Recall    = TP / (TP + FN)    "만들어야 할 것 중 얼마나 만들었나"
F1        = 조화평균           "둘의 균형"
```

## 짝짓기는 2단계다

```
정답 액션들          예측 액션들
     |                   |
     +--- [1] 규칙 매칭 ---+    <- 이름이 같으면 짝  (공짜, 확정적)
     |                   |
   남은 것             남은 것
     |                   |
     +--- [2] LLM 매칭 ---+    <- 이름은 다른데 같은 일인가?  (유료)
```

### [1] 규칙 매칭 (Rule Match)

**같은 이름이면 짝짓는다.** 단, "같은 이름"의 판단에 두 가지를 더한다.

**(a) 동치 규칙** — 같은 일을 하는 다른 패키지는 같게 본다.

Automation Anywhere는 같은 작업을 여러 패키지로 할 수 있다. 엑셀 파일을 만드는
방법만 세 가지다.

```
Excel.CreateSpreadsheet
Excel_MS.CreateSpreadsheet                                      전부 같은 것으로 취급
Microsoft 365 Excel...office365ExcelCreateWorkbook
```

메일 발송도 마찬가지다 (`Email.sendMail` = `Gmail.Send` =
`Microsoft 365 Outlook.ms365OutlookSend`).

현재 **45개 그룹**이 `evaluation/action_equivalence_rules.json`에 있다.
**규칙은 하나다: 같은 작업을 다른 패키지로 구현한 것만 묶는다.** 다른 작업을
비슷하다고 묶은 건 없다(전수 확인함).

**(b) 짝이 여러 개면 파라미터가 같은 것부터**

정답에 `File.copy`가 3개, 예측에도 3개 있으면 어떤 걸 어디에 붙일까?

1. 먼저 **파라미터(대상 텍스트, 동작 종류)가 완전히 같은 쌍**부터 붙인다
2. 남은 건 **등장 순서대로** 붙인다

순서만으로 무작정 붙이면 뒤에서 계산할 "순서 점수"가 왜곡되기 때문이다.

> **핵심**: 이 짝짓기는 **엄격한 1:1**이다. 예측 액션 하나는 **정답 액션 하나
> 에만** 붙는다. 그래서 예측 하나가 정답 여러 개에 중복 인정되는 일이
> **구조적으로 불가능**하다.

### [2] LLM 매칭 (Judge Match)

규칙으로 못 붙인 것 중에는 **이름은 다르지만 같은 일**인 경우가 있다. 예를 들어
`Recorder.capture`(화면 녹화 방식 클릭)와 `WebAutomation.clickelement`(요소 직접
클릭)는 이름이 전혀 다르지만 둘 다 "클릭"이다.

이걸 전부 LLM에게 물어보면 비용이 폭발한다(남은 게 각각 20개면 최대 400번).
그래서 **후보를 먼저 좁힌다.**

1. 남은 액션들을 문장으로 만들어 임베딩(`text-embedding-3-small`)한다
2. **서로가 서로를 1등으로 꼽은 쌍**만 고른다 (상호 Top-1)
3. 그 쌍만 LLM에게 "같은 동작인가?" 물어본다 → `same`이면 짝

400번이 20번 이하로 줄어든다. 그리고 **한 액션당 후보가 1개뿐**이라 "여러 개가
다 같다고 하면 뭘 고르지?" 하는 문제 자체가 안 생긴다.

**LLM 프롬프트에 명시한 것**:
- 상위 업무 목적이 같다는 이유만으로 같다고 하지 말 것. **각 액션 하나가 하는
  동작이 서로 대체 가능한지**만 볼 것
- 라벨이나 설명에 어떤 업무가 적혀 있어도, 실제 액션 목록에 없으면 그 업무를
  했다고 보지 말 것

## 그래서 지표가 두 벌 나온다

| 지표 | 매칭 | 성격 |
|---|---|---|
| **Rule-only** | 규칙만 | **공식 기준선.** LLM 없이 100% 재현됨 |
| **Judge-assisted** | 규칙 + LLM | 참고용. 실행마다 조금 달라질 수 있음 |

**공식 발표에는 Rule-only를 쓴다.** 누가 언제 돌려도 같은 숫자가 나와야
기준선이기 때문이다. (실제로 검증했다 → [05-validation.md](05-validation.md))

## 순서도 본다 — Action Chain

액션을 다 맞춰도 **순서가 뒤죽박죽이면** 제대로 된 워크플로우가 아니다.

짝지어진 쌍들을 **예측 순서대로** 늘어놓고, 그 정답 인덱스 수열의
**최장 증가 부분수열(LIS)** 길이를 구한다.

```
예측 순서:      A     B     C     D
정답 인덱스:    1     5     2     6
                └─ 1, 5, 6 이 증가 → LIS = 3

Chain Precision = 3 / 예측 액션 수
Chain Recall    = 3 / 정답 액션 수
Chain F1        = 조화평균
```

즉 **"순서를 지키면서 맞은 액션"만 센다.**

**해석 주의**: Chain F1은 순수 순서 점수가 **아니다.** 액션을 빠뜨리거나 쓸데없이
많이 만들어도 분모가 커져서 떨어진다. **"액션 선택 + 상대 순서를 함께 반영한
지표"** 로 읽어야 한다.

**교차 검증**: 같은 짝 위에서 LCS(최장 공통 부분수열)로도 계산해서 LIS와 같은
값이 나오는지 단위 테스트로 확인한다. 짝이 1:1로 확정된 상태에서는 두 방법이
수학적으로 같은 값을 내야 정상이고, 다르면 짝짓기 로직에 버그가 있다는 신호다.

## 보조 진단 — 분기가 얼마나 구현됐나

`if/elseIf/else`가 있는 워크플로우에서, 각 분기가 얼마나 채워졌는지 따로 본다.
**메인 점수에는 안 들어간다** — 왜 그 점수가 나왔는지 설명해주는 역할이다.

| 지표 | 계산 | 성격 |
|---|---|---|
| **Branch Coverage** | 완전히 구현된 분기 수 / 전체 분기 수 | 전부 아니면 0 (엄격) |
| **Branch Score** | 분기별 구현 비율의 평균 | 부분 점수 인정 (관대) |

```
분기 3개, 각각 2/3씩 맞음
  -> Branch Score    = (0.67 + 0.67 + 0.67) / 3 = 0.67   "평균 67% 구현"
  -> Branch Coverage = 0 / 3 = 0.00                      "완성한 분기는 없음"
```

**"절반 이상이면 인정" 같은 임의 임계값은 두지 않았다.** 근거를 댈 수 없는
숫자를 만들지 않기 위해서다. 핵심 액션이 아예 없는 분기(로그만 있는 분기)는
분모에서 빼서 억지로 0점 처리하지 않는다.

> 이 두 지표를 메인 F1에 더하거나 평균 내면 **안 된다.** 같은 액션이 두 번
> 반영된다. 실제로 "메인 지표를 분기 기준으로 교체하자"는 설계를 만들었다가
> 되돌렸다 → [appendix-c-rejected-designs.md](appendix-c-rejected-designs.md)

## 최종 지표 정리

| 구분 | 지표 | 역할 |
|---|---|---|
| **공식** | Rule-only Action P / R / F1 | 재현 가능한 기준선 |
| 참고 | Judge-assisted Action P / R / F1 | LLM 포함 시 얼마나 오르나 |
| 공식 | Action Chain F1 | 액션 선택 + 순서 |
| 보조 | Branch Coverage / Score | 분기를 얼마나 구현했나 |
| 외부 | WorFBench F1 | 외부 벤치마크 (직접 비교 불가) |
