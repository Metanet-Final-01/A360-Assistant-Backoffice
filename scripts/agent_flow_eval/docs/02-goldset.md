# 2. 정답 데이터셋(goldset) 만들기

## 왜 817개를 다 안 쓰나

Bot Store 봇 818개를 전부 정답으로 쓰면 좋을 것 같지만, 실제로 열어보면 상당수가
**평가 기준으로 쓸 수 없는 것들**이었다.

- 벤더가 기능 시연용으로 만든 예제 봇 (실제 업무가 아님)
- 워크플로우가 액션 2~3개뿐이라 비교할 게 없는 것
- 업무 목적을 사람이 읽어도 알 수 없는 것

정답지가 이상하면 점수도 의미가 없다. 그래서 **양보다 신뢰도**를 택했다.

## 선별 과정

```
817개 goldset
   |  자동 선별: 액션 수, 제어 구조 유무, RAG 커버리지 등으로 후보 좁히기
   v
34개 후보 풀 (candidate_pool/)
   |  1차: GPT가 "실제 업무인가" 분류
   v
후보 축소
   |  2차: Claude와 Codex가 각각 독립적으로 재검토
   v
9개 확정 (둘 다 인정한 것만)
```

### 자동 선별에서 본 것

`analysis/select_eval_candidates.py`, `analysis/check_rag_coverage_tiered.py`가
후보를 좁혔다. 중요한 기준 하나는 **RAG 커버리지**다 — 에이전트가 액션을
추천하려면 그 액션이 사내 RAG 문서에 있어야 한다. 문서에 아예 없는 액션을 쓴
봇을 정답으로 삼으면, 에이전트가 아무리 잘해도 맞출 수 없다.

### 사람 교차검수 (핵심)

**Claude와 Codex가 서로 결과를 모르는 상태에서 각각 검토하고, 둘 다 "쓸 수
있다"고 한 것만 확정했다.** 한쪽만 인정한 것은 제외했다.

실제로 이 방식이 작동한 사례:

- **0164** — 한 번 "유틸리티성이라 업무가 아니다"로 제외됐다가, "그럼 같은
  성격인 0085/0112도 빼야 하는데 그건 인정했지 않느냐"는 반박이 받아들여져
  다시 포함됐다.
- **0381** — 벤더 CRUD 예제 봇으로 확인되어 **확정 제외**.
- **0080 / 0307** — 현재 채점기가 이 두 봇의 핵심 속성(연결 방식, DMN·Twilio
  파라미터)을 비교하지 못해서 **보류**. 채점 못 하는 걸 억지로 넣지 않았다.

> 문서를 쓴 것과 정답으로 확정한 것은 다르다. 업무정의서를 작성했더라도
> 교차검수를 통과하지 못하면 확정 목록에 넣지 않는다.

## 업무정의서(문제지)는 어떻게 썼나

**사람이 실제 정답 액션 시퀀스를 보면서 직접 작성했다.** LLM에게 자동 생성시키지
않았다 — 그러면 "정답을 그대로 베낀 문제지"가 되어 에이전트가 부당하게 쉬워진다.

형식은 이렇다.

```markdown
# 업무 정의서

과제명: 폴더 내 파일 보관(아카이브) 처리

## Task 1 — 실행 준비 (로그 구성)
작업 순서:
1. 오늘 날짜 기준으로 감사 로그·오류 로그·스냅샷 폴더를 만든다
2. 로그 파일이 없으면 만든다
3. 보관 기간이 지난 이전 로그 폴더는 삭제한다

## Task 2 — 보관 폴더 준비
...
```

핵심 규칙:

- **"무엇을" 만 쓰고 "어떤 액션으로"는 안 쓴다.** "Excel_MS.CreateSpreadsheet를
  호출한다"가 아니라 "결과를 엑셀 파일로 저장한다"라고 쓴다. 그래야 에이전트가
  스스로 액션을 고르는 능력을 잰다.
- **작성 후 파싱 검증을 거친다.** 기계가 Task 구조를 읽을 수 있어야 한다.

이 업무정의서는 채점에서도 쓰인다 — 어떤 액션이 "이 업무의 핵심인지" 판단할 때
LLM에게 이 원문을 그대로 보여준다([03-preprocessing.md](03-preprocessing.md) 참고).

## 폴더 구조

```
goldset_expansion/confirmed_goldset/
  README.md            현재 확정 상태
  briefs/              업무정의서 9개 (.md)  <- 문제지
  gold/                정답 워크플로우 9개 (.goldset.json)  <- 정답지
  pdfs/                에이전트 입력용 PDF (재생성 가능, git에 안 올림)
  evaluation_results/  최종 채점 결과 (엑셀 + 마크다운)
```

**정답 파일은 `gold/` 안의 것이 유일한 기준이다.** 예전에는 채점기가 git에
올라가지 않는 임시 폴더를 읽고 있었는데(그래서 새로 내려받으면 채점이 아예
안 됐다) 2026-08-03에 `gold/` 하나로 통일했다.
